# План редизайна KILENI

## Цель

Собрать цельный публичный продукт вокруг бесплатной SEO-проверки: понятный первый экран, надёжный аудит до 100 страниц, доказательные кейсы, разделённые услуги, сильный блог и короткий бриф. Текущий backend и защитные контракты сохраняются.

## Этап 1. Фундамент

- Свести палитру, типографику, сетку, отступы и состояния в один слой токенов.
- Ввести темы `light`, `dark`, `signal`; переключатель циклический и хранит выбор локально.
- Сохранить словесный логотип отдельным компонентом; не менять знак.
- Убрать конфликт старой 12-колоночной и новой двухколоночной hero-сетки.
- Укоротить декоративное интро так, чтобы полезный контент не ждал его завершения.

## Этап 2. Главный конверсионный сценарий

- Новый H1: «Сайт есть. Пора сделать так, чтобы его находили.»
- URL показывается сразу; имя/e-mail/согласия раскрываются только после валидного адреса.
- Лимит задаёт сервер: максимум 100 публичных страниц, без пользовательского ползунка.
- Визуал: маркетинговый аналитический дашборд с явной подписью демо-режима; при реальном аудите он показывает фактический прогресс.
- Социальное доказательство: только число уникальных нормализованных доменов с реально завершённым аудитом; при нуле блок скрыт.
- Результат/PDF и e-mail не заявляются успешными, пока соответствующая интеграция не подтвердила действие.

## Этап 3. Навигация и маршруты

- Верхний уровень: Услуги, Маркетплейсы, Кейсы, Цены, Блог, Бриф, язык, тема, CTA.
- `Услуги`: SEO-аудит, SEO-продвижение, Разработка сайтов, Яндекс Реклама.
- `Маркетплейсы`: обзор, Wildberries, Ozon, Яндекс Маркет, Мегамаркет.
- Новые RU/EN маршруты:
  - `/blog` и `/en/blog` с совместимым redirect с `/articles`;
  - `/glossary` и `/en/glossary`;
  - `/marketplaces/{wildberries,ozon,yandex-market,megamarket}` и EN-аналоги.
- Sitemap, canonical, hreflang, breadcrumbs и внутренние ссылки обновляются одновременно.

## Этап 4. Контентные шаблоны

- Услуги: задача → признаки → состав → результат → ограничения → сроки/цена → следующий шаг.
- Маркетплейсы: собственная посадочная каждой площадки с официальными терминами и логотипом без заявления партнёрства.
- Кейсы: бизнес-задача → что нашли → что исправили → повторная проверка → подтверждённые числа → ограничение.
- Блог: категории, фильтр, оригинальные редакционные иллюстрации, «что узнаете», источники, glossary-links и следующий шаг.
- Глоссарий: не менее 27 терминов с простым объяснением, значением для бизнеса, примером и ссылкой на материал/услугу.

## Этап 5. Коммерческие страницы

- Прайс: три уровня внутри выбранной категории, один рекомендуемый, явные лимиты, состав и CTA.
- Числа остаются из `src/config/prices.ts`; 25% разрешены только для первого платного SEO-аудита.
- EN без утверждённой валютной конфигурации показывает `Individual estimate`, а не автоматический USD.
- Бриф: короткий сценарий 5–7 минут, возможность «не знаю», динамический состав и итог перед отправкой.

## Этап 6. Privacy и качество

- Сначала инвентаризация реально используемых cookies/storage/аналитики.
- Затем менеджер согласий с необходимыми, аналитическими и маркетинговыми категориями; отказ так же доступен, как согласие.
- Проверки: 320, 360, 390, 768, 1024, 1280, 1440, 1920, 2560 px; RU/EN; три темы; reduced-motion; клавиатура; Axe.
- E2E: главная → аудит → результат/PDF → следующий шаг; прайс → пакет → бриф; blog/glossary; marketplace routes.
- Финальные команды: lint, typecheck, unit/integration, E2E, production build, Lighthouse.

## Границы изменений

- Не менять production-настройки, не коммитить и не пушить без отдельного разрешения.
- Не добавлять платные сервисы и не публиковать фиктивные отзывы, партнёрства, награды или результаты.
- Не удалять существующие пользовательские файлы и параллельные изменения.
- Preview-деплой допускается только после зелёной сборки и явного разрешения владельца.

## Порядок внедрения

1. Фундамент, header, темы и новый hero/audit-flow.
2. Навигация и маршруты.
3. Кейсы, услуги, marketplace landing pages.
4. Прайс, бриф, блог, глоссарий.
5. Privacy, SEO, accessibility, производительность.
6. Полный визуальный и функциональный прогон; только затем preview.
