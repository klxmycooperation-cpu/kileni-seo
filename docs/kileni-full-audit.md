# Полный внутренний аудит KILENI

Дата: 5 сентября 2026 года
Production: `https://kileni-seo.ru`
Метод: read-only crawl production, затем performance/accessibility/browser QA на preview. Production-код, runtime и маршрут не переключались. Ранние preview-запуски могли создать QA-записи в production Turso до исправления изоляции; это ограничение описано ниже.

- RU HTML-состояний: 120; EN: 120.
- P0: **0**.
- Подтверждённые P1 сайта: тяжёлые eager-изображения; недоступное с клавиатуры/скринридера содержимое desktop-блоков «О компании»; нарушенный порядок заголовков в брифе; недостаточный контраст элементов в нескольких темах и размерах. Все четыре исправлены в preview.

## On-page

Полный production-crawl не нашёл:

- отсутствующих title, description или H1;
- нескольких H1;
- нарушений по собственной упрощённой проверке server HTML; отдельный browser/Axe-проход при этом воспроизвёл один более точный дефект порядка заголовков в интерактивном брифе, поэтому он классифицирован ниже как P1 и исправлен в preview;
- слишком коротких/длинных description по используемым границам;
- thin content;
- точных content duplicates;
- duplicate title/description groups.

Соответствие текста назначению страницы проверено вручную только на девяти обязательных шаблонах — главной, services, SEO, pricing, free-audit, brief, кейсе, статье и glossary. Явного несоответствия pageType и видимого содержания в этой выборке нет. Полная смысловая редакторская оценка всех 240 HTML-состояний не автоматизировалась — **NOT TESTED для всего inventory**; word count, hash и metadata не выдаются за доказательство смысла текста.

Зафиксированы 24 группы одинаковых H1 в RU/EN-парах терминов: `LCP`, `CLS`, `Title`, `robots.txt` и другие международные обозначения. Это не машинный дубль содержимого и не основание переписывать принятые страницы — **DO NOT CHANGE**.

## Производительность

Проведено по три desktop и mobile запуска для главной, services, SEO, pricing, free-audit, brief, кейса, статьи и glossary. Сохранены JSON всех запусков и медианы.

### Что подтвердилось

Production-главная загружала около 2,27 МБ в mobile-профиле, медиана mobile Lighthouse — 69, LCP — около 8,0 с. Статья в том же mobile-профиле загружала около 4,05 МБ, score — 59, LCP — около 20,6 с. В отдельно повторённом корректном desktop-профиле статья загружала около 2,20 МБ, получила 90, LCP — около 2,01 с. Trace и network inventory подтвердили существенную часть причины: исходный PNG около 1,87 МБ и eager-загрузка изображений вне первого экрана.

На production также повторился высокий mobile TBT: кейс — 293 / 376,5 / 379 мс, статья — 477 / 600 / 8 мс. По принятому критерию это подтверждает проблему у кейса в трёх запусках и у статьи в двух из трёх. Финальный внешний HTTPS-preview после исправлений этого не воспроизводит: медиана кейса — 53 мс, статьи — 31,5 мс; ни один из трёх запусков каждого маршрута не превысил 200 мс. Отдельную единственную причину старого TBT trace не доказал, поэтому результат считается устранённым на preview по повторному измерению, но требует контрольного замера после будущей публикации.

В preview изображения переведены в WebP, offscreen-карточки загружаются lazy, hero статьи получает `fetchPriority=high`. Во внешнем HTTPS-прогоне вес составил:

- главная: примерно 419 КБ desktop / 406 КБ mobile;
- статья: примерно 562 КБ desktop / 556 КБ mobile.

Финальный внешний HTTPS-preview после изоляции стенда: главная mobile 91 / LCP 3,12 с / TBT 54 мс, desktop 99 / LCP 0,84 с / TBT 0 мс; статья mobile 93 / LCP 2,72 с / TBT 31,5 мс, desktop 95 / LCP 0,85 с / TBT 0 мс. Ни на одном из девяти маршрутов не подтвердился TBT-дефект уровня P1: для каждого профиля выполнено по три одинаковых запуска, и повторного превышения TBT 200 мс нет. Это не означает отсутствия всех performance-рисков: LCP главной превысил 2,5 с в двух из трёх mobile-запусков, LCP статьи — в трёх из трёх, CLS брифа составил 0,11 во всех трёх mobile-запусках. У `/seo` desktop и `/free-audit` mobile медиана лабораторной оценки равна 89, но LCP и TBT не подтверждают критическую блокировку; эти наблюдения оставлены P2 без спекулятивной переделки. Все значения — лабораторные данные preview, а не показатели реальных посетителей.

### Ограничение интерпретации mobile

Локальный HTTP standalone-прогон сохранён только как ранняя диагностика и не используется для сравнения с production. Итоговая регрессия измерена на внешнем HTTPS-preview. Для главной дополнительная причина реальна: accepted intro длится около 4,2 с при первом входе. Возвращающийся посетитель intro не видит. Визуальную концепцию и утверждённую скорость intro не меняли — **DO NOT CHANGE без продуктового решения**.

## Accessibility и UX

Основная матрица проверила 36 комбинаций маршрутов, размеров, тем и браузеров. Финальный расширенный contrast-pass отдельно проверил 84 комбинации: 7 маршрутов × 3 темы × 2 viewport × Chromium/WebKit. До исправления desktop `<details>` на странице «О компании» выглядели раскрытыми из-за CSS, но оставались закрытыми в accessibility tree. Теперь desktop-состояния реально открыты, на mobile остаются компактными disclosures.

Первый production Axe-проход подтвердил serious `color-contrast` на `/services`, `/seo`, `/glossary/lighthouse`, `/checks/http-status`, `/contacts`, а в mobile-сценариях — дополнительно на `/`, `/pricing` и `/services`. Расширенная контрольная матрица воспроизвела 62 serious/critical вхождения по сценариям baseline; в том числе отдельно выявила слишком бледные хлебные крошки светлой темы на `/seo`, `/glossary/lighthouse` и `/checks/http-status`. Цвета исправлены локальными theme-scopes без изменения композиции. Та же матрица на итоговом preview: 84/84 сценария, serious/critical — 0, HTTP-ошибки — 0, horizontal overflow — 0, отсутствующие визуальные цели — 0.

В брифе Axe находил moderate `heading-order`: визуальный блок начинался с H3 без H2. Добавлен скрытый смысловой H2 без изменения макета.

После исправлений:

- serious/critical Axe: 0;
- horizontal overflow: 0;
- console errors: 0;
- page errors: 0;
- неуспешные HTTP-состояния в проверенных сценариях: 0.

Остался minor `aria-allowed-role` у нескольких существующих tabpanel-контейнеров на `<article>`. Он не ломает управление или имя элемента; классификация P2, в этот release-pass не включён.

## Классификация

### P0

Не найдено.

### P1 — исправлено в preview

1. Тяжёлые PNG и eager offscreen-loading на главной/статьях.
2. Desktop-содержимое «О компании» отсутствовало в accessibility tree, несмотря на визуально раскрытый вид.
3. Нарушение heading order в интерактивном брифе.
4. Недостаточный цветовой контраст текста и состояний на нескольких маршрутах в desktop/mobile темах.
5. Hreflang мог применяться к странице без реально обнаруженной языковой пары и создавать ложное замечание.
6. Noindex выбранной публичной utility/conversion-страницы мог отсутствовать в её карточке и findings.

### Подтверждённый production performance-сигнал, не воспроизведённый в preview

Mobile TBT кейса и статьи превышал 200 мс минимум в двух из трёх production-запусков. Внешний preview после исправлений прошёл по три запуска с TBT ниже 200 мс. Точная изолированная причина старого TBT не доказана; обязательное действие — повторить три запуска после будущего production deployment.

### P2 / наблюдение

1. Accepted brand intro влияет на LCP первого мобильного входа; в финальном прогоне LCP превысил 2,5 с в двух из трёх запусков (1,94 / 3,20 / 3,12 с). Изменение требует отдельного продуктового решения.
2. Mobile LCP статьи превысил 2,5 с в трёх из трёх финальных запусков (2,75 / 2,72 / 2,71 с); TBT при этом стабильно низкий. Нужны полевые данные и отдельная точечная диагностика, а не спекулятивная переделка.
3. Mobile CLS брифа равен 0,11 во всех трёх внешних preview-запусках; в browser QA видимого скачка и overflow не воспроизведено, поэтому нужен отдельный воспроизводимый сценарий или полевые данные.
4. Axe minor `aria-allowed-role` на существующих tabpanel-контейнерах.
5. Одинаковые названия международных терминов в RU/EN — намеренно, не SEO-дубль.
6. Вход через `http://www` использует два redirect-hop вместо одного; все переходы корректны и ведут на канонический HTTPS-хост.

### NOT TESTED

- фактическая индексация, позиции, показы и CTR;
- поисковой спрос и каннибализация запросов;
- полная смысловая редакторская оценка соответствия текста назначению каждой из 240 HTML-страниц; вручную просмотрены девять основных шаблонов;
- полевые Core Web Vitals реальных посетителей;
- трафик, заявки и конверсии без analytics/search-console access;
- внешняя доставляемость email из preview;
- причинная привязка hydration, количества event listeners и всех offscreen-анимаций к конкретному компоненту; сохранённый trace и Lighthouse уже проверили TBT, long tasks, JavaScript execution, main-thread work, third-party insight, intro и загрузку ресурсов, но не дают основания приписывать остаточную задержку неподтверждённому механизму.
