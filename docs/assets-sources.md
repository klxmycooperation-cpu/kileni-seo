# Источники и статус ассетов

Документ нужен для контроля происхождения визуальных и скачиваемых материалов перед публикацией.

## Проектные ассеты

| Путь | Назначение | Источник и статус |
|---|---|---|
| `public/brand/kileni-logo-light.svg` | Логотип на светлом фоне | Проектный вектор KILENI, создан для этой сборки; внешние элементы не указаны |
| `public/brand/kileni-logo-dark.svg` | Логотип на тёмном фоне | Проектный вектор KILENI, создан для этой сборки |
| `public/brand/kileni-logo-mono.svg` | Монохромная версия | Производная от проектного знака |
| `public/brand/kileni-mark.svg` | Компактный знак и favicon-основа | Проектный вектор KILENI |
| `public/brand/kileni-og.svg` | Open Graph 1200×630 | Проектная композиция из знака, текста и геометрической сетки |
| `public/brand/kileni-og.png` | Растровая OG-версия | Рендер `kileni-og.svg`, 1200×630 |
| `public/editorial/*.svg` | Обложки четырёх статей | Проектные абстрактные SVG-иллюстрации, созданные для этой сборки; внешние фотографии не используются |
| `public/downloads/generated/*` | RU/EN брифы DOCX/PDF | Генерируются `scripts/generate-briefs.mjs` из собственного текста и проектной верстки |

В PDF шрифт встраивается из TTF, указанных `BRIEF_FONT_REGULAR` и `BRIEF_FONT_BOLD`. Docker-сборка использует пакет Debian `fonts-dejavu-core`. DOCX задаёт семейство Arial, но сам файл шрифта не встраивает: конечная подстановка зависит от офисного приложения пользователя.

Интерфейс использует Manrope, Inter и IBM Plex Mono через `next/font/google`. Next загружает их во время сборки и раздаёт локально из build output. При сборке в изолированной сети нужно заранее обеспечить разрешённый источник или заменить их на проверенные локальные файлы.

## Редакционные источники

Ссылки на Google Search Central, Яндекс, Wildberries и Ozon в `src/content/articles.ts` являются источниками фактов, а не визуальными ассетами. Текст статей — самостоятельная редакционная работа; длинные фрагменты источников не копируются.

Данные кейсов получены из предоставленных заказчиком DOCX-аудитов и сведены в `docs/case-evidence.md`. Исходные документы не находятся в `public/` и не входят в Docker image.

## Legacy-файлы с неподтверждённым происхождением

Следующие файлы остались от прежнего starter-содержимого и не используются актуальными страницами KILENI:

- `public/images/fragrances/kileni-01.jpg`;
- `public/images/fragrances/kileni-02.jpg`;
- `public/images/fragrances/kileni-03.jpg`;
- `public/file.svg`, `public/globe.svg`, `public/window.svg`.

Происхождение и лицензия JPG не подтверждены. `.dockerignore` исключает эти legacy-файлы из production Docker build. До подтверждения прав их нельзя возвращать в интерфейс или переносить в production другим способом. Удаление из рабочего дерева требует отдельного согласования, поскольку это пользовательские файлы.

## Release-проверка

Перед добавлением нового ассета зафиксируйте:

1. автора или официальный источник;
2. тип лицензии и допустимость коммерческого использования;
3. необходимость атрибуции;
4. исходный URL и дату получения для внешнего материала;
5. согласие изображённых людей и права на товарные знаки, если применимо;
6. оптимизированный формат, размеры, alt и отсутствие скрытых метаданных.

Не используйте изображения из поисковой выдачи без отдельной проверки лицензии.
