# Проверка после изменения или восстановления

## Локальный обязательный набор

Запускайте из корня репозитория после `pnpm install --frozen-lockfile`:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

`pnpm test:e2e` должен выполняться на отдельной тестовой БД и без production SMTP, Telegram, Turso и uploads. Перед выпуском повторите выбранные tests на production build с `E2E_PRODUCTION_SERVER=1`.

## Сквозные сценарии

### Аудит

Создайте новый audit на контролируемом публичном URL. Проверьте запись job, worker heartbeat, несколько progress events, terminal status, сохранённую публичную ссылку, API, PDF и тот же audit в admin. Проверяйте фактические counts: результат с обнаруженными URL и нулём выбранных или нулём подробно проверенных страниц не должен считаться корректно завершённым.

### Почта

Используйте контролируемый mailbox. Проверьте отдельные факты: SMTP принял сообщение, письмо появилось во входящих, ссылка внутри него открывает нужный audit. Только третья проверка подтверждает доставку. Ошибка SMTP не должна отменять сохранение audit или brief. Для audit `notification_events` поддерживает безопасный retry worker-ом; для brief сейчас сохраняется результат попытки, а повторная отправка требует отдельного контролируемого действия.

### Бриф

Выберите направление и тариф, заполните обязательные поля, приложите допустимый test file и отправьте форму. Убедитесь, что bриф сохранён в БД, отображается в admin, вложение скачивается только после входа, а повторное нажатие не создаёт второй бриф. Если настроено уведомление, проверьте его как отдельный канал.

### Старые данные и перезапуск

После штатного рестарта web/worker откройте несколько прежних audit URL, PDF, lead и brief. Временное отключение сети в браузере не должно очищать заполненную форму; повторная отправка должна быть идемпотентна либо вернуть понятный конфликт без потери данных.

## Визуальная приёмка

Проверьте `/`, `/services`, `/pricing`, `/free-audit`, `/brief`, result audit и admin в Dark, Signal и Light на 1440, 768, 390 и 320 px. Нужны заполненные формы, выбранный тариф, загрузка вложения, открытые состояния результата и error/success states. Смотрите на contrast, overflow, переносы, изображения, CSS/JS/fonts, focus, console и network errors. Сохраняйте screenshots без персональных данных и короткую запись audit/brief flow.

## Production наблюдение

После публикации сохраните timestamps десяти external health checks и нескольких API requests за 15 минут. Один успешный ответ сразу после restart не является доказательством стабильного release.
