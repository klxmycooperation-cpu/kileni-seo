# Smoke-test движка бесплатного аудита

Дата: 4 сентября 2026 года
Ветка: `audit/kileni-full-validation`
Область: три полностью контролируемых сайта, без обращений к production.

## Результат

Все три обязательных fixture-сайта проходят. Проверены функции анализатора и итоговый путь одного immutable snapshot через API, web, PDF и admin в Chromium и WebKit. Равенство нормализованной client model проверяется автоматически; итоговые отображаемые строки и композиция web/PDF/admin дополнительно сверены глазами по сохранённым артефактам.

| --- | ---: | ---: | ---: | ---: | --- |
| A — небольшой лендинг | 3 | 3 | 3 / 3 | 0 | PASS |
| B — интернет-магазин | 9 | 5 | 5 / 5 | 4 | PASS |
| C — RU/EN | 9 | 9 | 6 / 6 | 0 | PASS |

Автоматическая проверка fixture-логики и model parity: 8 suites, 60 tests, 60 passed. Browser E2E: Chromium PASS, WebKit PASS. Это не объявляется полным автоматическим посимвольным сравнением всех четырёх отрисованных поверхностей: rendered parity подтверждён визуально и извлечённым текстом PDF.

## Какие проверки фактически выполнялись

Для всех выбранных HTML-страниц движок проверил HTTP-ответ, запрет `noindex`, canonical, title, description, H1, порядок заголовков, внутренние ссылки, язык документа и mobile viewport. Условные проверки запускались только при наличии основания: hreflang — у найденной языковой пары, Product — у карточки товара, BreadcrumbList — у внутренней иерархической страницы, форма — при найденной форме. Проверка скорости в fixtures намеренно не имитировалась и получила `not_run`: Lighthouse проверялся отдельно на реальном preview.

На уровне сайта во всех трёх сценариях проверены HTTPS, конечный адрес после перенаправлений, доступность выбранных страниц, robots.txt, блокировки важных страниц правилами robots.txt и найденные языки. Позиции, показы, фактическая индексация и трафик получили `insufficient_data`, поскольку fixtures не подделывают данные поисковых кабинетов и аналитики.

Login и account в B распознаны пассивно и исключены до HTML-проверок: аудит не отправлял формы и не выполнял вход. Поэтому `auth` у выбранных страниц корректно имеет статус «не применяется», а у исключённых закрытых страниц не создаёт клиентских замечаний.

## Fixture A

Сайт состоит из главной, услуги и контактов. Sitemap отсутствует. Форма есть только на `/contact`. На `/services/launch` намеренно отсутствует title.

Подтверждено:

- лимит десять не создаёт искусственные страницы;
- отсутствие sitemap — предупреждение, но не критическая ошибка;
- title-дефект привязан только к `/services/launch`;
- форма положительно проверена только на `/contact`, на остальных страницах проверка не применяется;
- auth-check не применяется, потому что признаков входа нет;
- web, PDF, API и admin получают одинаковые counts, URL и выводы.

## Fixture B

В загруженный HTML inventory входят главная, категория, три товара, корзина, поиск, login и account. Параметризованный фильтр обнаруживается отдельно и отсекается до загрузки. У одного товара намеренно стоит noindex.

Подтверждено:

- сначала выбираются главная, категория и все три товара;
- корзина, поиск, параметризованный фильтр, login и account не вытесняют коммерческие страницы;
- клиентская арифметика не смешивает предварительно отфильтрованный query-URL с четырьмя исключёнными HTML-страницами: `9 = 5 + 4`;
- Product-проверки запускаются только для товаров;
- login и account пассивно распознаны по форме с паролем; `authSignals` есть только у `/login` и `/account`;
- эти закрытые страницы не входят в публичную SEO-выборку, аудит не вводит учётные данные и не выполняет активный вход;
- остальные страницы магазина не получают признаков авторизации; служебные состояния не создают ложный SEO-дефект;
- noindex у товарной страницы создаёт конкретную ошибку именно для неё;
- robots.txt и sitemap.xml не входят в HTML-выборку;
- одинаковый товарный шаблон не исключает остальные товары.

## Fixture C

Fixture содержит RU и EN, пять разных типов основной локали, валидные языковые пары, ровно одну отсутствующую пару и одну уникальную страницу с неверным canonical.

Подтверждено:

- сначала выбраны `/`, `/services/seo`, `/pricing`, `/cases/localization`, `/blog/a`;
- последней выбрана ровно одна EN-страница `/en`;
- оставшиеся языковые копии не занимают выборку;
- для `/services/seo`, где языковая пара реально обнаружена, hreflang проверяется и проходит;
- для `/pricing`, у которой alternate-страница не обнаружена, проверка получает понятный статус «не применяется», а не ложное предупреждение;
- canonical-предупреждение относится только к `/cases/localization`;
- ошибочный non-self canonical не превращает отличающийся контент в подтверждённый дубль.

## Обнаруженные и исправленные ошибки движка

1. Уникальная страница с ошибочным non-self canonical могла быть исключена как дубль до сравнения содержимого. Теперь исключение разрешено только при воспроизводимом подтверждении alias/redirect/canonical-дубля; иначе страница остаётся eligible и получает canonical finding.
2. Слабые признаки в URL могли переоценивать login/account и тип страницы. Классификация теперь опирается на наблюдаемое содержимое, schema и локаль; низкая уверенность остаётся `unknown`, а не выдуманным типом.
3. Вторичная локаль могла занять слот до покрытия уникальных типов основной локали. Сначала выбираются разные важные типы основной локали, затем максимум один alternate-locale контроль.
4. Поздний progress/failure event мог спорить с уже сохранённым terminal state. Финализация сделана атомарной: успешный результат или ошибка не перезаписываются опоздавшим событием.
5. Клиентские представления могли расходиться, если строились из разных промежуточных данных. API, web, PDF и admin теперь строятся из одного сохранённого snapshot и одной нормализованной клиентской модели.
6. Проверка hreflang раньше применялась ко всем страницам многоязычного сайта, даже когда у конкретной страницы не было обнаруженной языковой пары. Теперь применимость определяется для самой страницы по сохранённой разметке или реально найденному counterpart.
7. `noindex` на выбранной conversion/utility-странице мог не попасть в finding, из-за чего общий вывод и карточка URL расходились. Проверка индексирования теперь охватывает такие публичные страницы; закрытые, legal, cart/search/filter по-прежнему не получают ложную коммерческую рекомендацию.
