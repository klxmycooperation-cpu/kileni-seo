# Kileni SEO: тексты, изображения и финальная проверка

Дата: 11 сентября 2026. Изменения выполнены локально, без публикации, commit или push.

## Что изменено

- Генератор сообщения заказчику использует сохранённые факты, разделяет результат, возможное влияние и действие. Performance не превращается в утверждение о LCP, JavaScript, изображениях или поведении посетителей. Это детерминированный генератор, поэтому исправлена логика, а не только инструкция модели.
- Различаются LCP, CLS, TBT, отсутствие/дублирование/длина метаданных, количество H1, canonical, noindex и HTTP-ответы. Учтены намеренный noindex, отсутствие noindex, HTTP 304, незавершённая проверка и необязательные улучшения. Указаны адреса, охват проверки и её ограничения.
- Блок услуг со скриншота получил конкретный заголовок «От структуры страниц до работающего сайта». Для остальных услуг заголовки соответствуют их содержанию.
- В разделе команды исправлены текст и обрезание первой буквы. Причина — `overflow: clip` со скруглением на сетке без внутренних отступов. То же исправлено у соседнего блока передачи материалов. Геометрия и дизайн сохранены.
- Исправлено разбиение английских пунктов услуг после автоматического добавления ссылок на термины: текст каждого пункта теперь остаётся в общей колонке.
- Отредактированы найденные неточности в RU/EN: главная, услуги, компания, стоимость, бесплатный аудит, блог, справочник проверок и терминов. Убраны необоснованные причинные выводы; уточнены Accessibility, пустой alt, размеры изображений, HTTP 304 и различия мобильного/настольного теста.
- Для изображений Next оставлен WebP вместо серверного AVIF-кодирования по первому запросу. Адаптивные размеры, отложенная загрузка, качество и суточный кэш сохранены. Исходные фотографии не заменялись.

Корректные тексты, цены, кейсы и состав предложений сохранены. Автоматическая проверка всех маршрутов не равнозначна полной ручной построчной вычитке всего архива публикаций. Логика проведения SEO-аудита и интерфейс админки не менялись.

## Измерения изображений

На опубликованном сайте при профилировании холодных AVIF-ответов наблюдалось ожидание сервера около 0,8–1,7 с; передача небольших файлов занимала значительно меньше. Повторные тёплые ответы были быстрее. Это указывает на вклад подготовки/кэширования изображения, но не доказывает единственную причину задержек каждого посетителя.

Изолированный тест кодирования с параметрами установленного Next: медиана трёх запусков AVIF 190 мс, WebP 57 мс. Компромисс — WebP в этом образце больше: 21 314 против 12 903 байт. Это скорость кодирования, не всей страницы.

В локальной production-сборке запрос `/_next/image?url=%2Feditorial%2Fwebsite-speed-loading-v2.webp&w=828&q=60` с Accept, включающим AVIF:

- Content-Type: image/webp, Content-Length: 19 324;
- Cache-Control: public, max-age=86400, must-revalidate;
- первый запрос: MISS, TTFB около 64 мс;
- повторный: HIT, TTFB около 3 мс.

Локальные измерения нельзя напрямую сравнивать с удалённым сервером. Ускорение опубликованной версии нужно подтвердить после развёртывания.

## Команды и запуск

Запуск проекта по существующему README: Node >=22.13.0, pnpm 10.33.0, заполнить локальное окружение по `.env.example`, затем `pnpm dev` (web + worker). Production: `pnpm build`, `pnpm start`, отдельно `pnpm worker:start`.

В этой среде Corepack не прошёл проверку подписи pnpm; проверки запускались напрямую установленными инструментами, без отключения проверки целостности:

```powershell
.\node_modules\.bin\vitest.cmd run --config vitest.config.ts
.\node_modules\.bin\eslint.cmd . --max-warnings=0
.\node_modules\.bin\tsc.cmd --noEmit
.\node_modules\.bin\tsc.cmd -p tsconfig.worker.json --noEmit
node node_modules/next/dist/bin/next build --webpack
node scripts/prepare-standalone-assets.mjs
.\node_modules\.bin\esbuild.cmd worker/index.ts --bundle --platform=node --format=esm --packages=external --outfile=dist-worker/worker.js
node scripts/start.mjs
.\node_modules\.bin\playwright.cmd test tests/e2e/final-copy-and-images.spec.ts --project=chromium
.\node_modules\.bin\playwright.cmd test tests/e2e/final-copy-and-images.spec.ts --project=chromium --project=webkit --grep 'team section|glossary links'
node tmp/final-visual.mjs
git diff --check
```

Браузерные команды использовали изолированный локальный сервер, отдельную SQLite, пустые внешние интеграции и `E2E_EXTERNAL_SERVER=1`; не запускать их против рабочего сайта или рабочей базы. esbuild потребовал разрешённый запуск вне песочницы из-за запрета чтения родительского каталога.
