# Предварительная SEO-оценка KILENI

## Назначение

Оценка отражает только наблюдаемую публичную часть сайта. Это внутренняя шкала KILENI, а не показатель Яндекса, Google, Lighthouse или PageSpeed. Она не заменяет расширенный аудит с доступом к аналитике, поисковым кабинетам, CMS и серверу.

Расчёт детерминирован: одинаковые входные наблюдения дают одинаковый результат. Случайные числа и заранее записанные штрафы не используются.

## Итоговые категории

| Категория | Максимум |
|---|---:|
| Техническая доступность и индексирование | 30 |
| Структура и on-page | 25 |
| Скорость и мобильность | 20 |
| Доверие и структурированные данные | 15 |
| Контент и изображения | 10 |
| Итого | 100 |

## Формула

Для проверки `i` определены:

- `wᵢ` — внутренний вес;
- `vᵢ` — наблюдаемое качество от `0` до `1`; `null`, если данных нет;
- `cᵢ` — покрытие наблюдения от `0` до `1`.

Сначала вычисляется сырое качество категории только по применимым проверкам:

```text
quality = Σ(vᵢ × wᵢ) / Σ(wᵢ для vᵢ ≠ null)
```

Покрытие категории учитывает и отсутствующие данные:

```text
coverage = Σ(cᵢ × wᵢ) / Σ(wᵢ всех проверок)
```

При неполном покрытии действует ограничитель уверенности:

```text
confidence = 0,5 + coverage / 2       если coverage < 1
confidence = 1                         если coverage = 1
categoryScore = round(categoryMax × quality × confidence)
```

Итог — сумма пяти категорий. Общее покрытие — среднее покрытие категорий с весами `30/25/20/15/10`.

Такой подход не подменяет неизвестное нулём, но и не позволяет одной удачно проверенной странице дать сайту необоснованные 100 баллов.

### Техническая доступность и индексирование — 30

|---|---:|---|

| Доступ по robots.txt | 4 | разрешённый корень = 1; запрещённый = 0; неизвестно = `null` |
| Наличие robots.txt | 2 | найден = 1; отсутствует = 0; ошибка чтения = `null` |
| XML sitemap | 4 | корректно найдена = 1; отсутствует = 0; недоступна = `null` |
| Кодировка | 3 | доля страниц с определённым charset |

| Проверка | Вес | Значение |

Между хорошей и плохой границей используется линейная интерполяция. Lighthouse запускается максимум для трёх страниц. Если Chrome, proxy или метрика недоступны, значение остаётся `null` — оно не выдумывается.

Порог тонкой страницы — приблизительно 100 слов видимого текста. Это диагностический сигнал, а не универсальная рекомендация увеличить текст любой ценой.

## Ограничение двойных штрафов

- Отсутствующий title не получает одновременно штраф за длину: проверки взаимоисключающие.
- Ошибки, сохранённые в `audit_issues`, сами по себе не вычитают баллы. Балл меняют только перечисленные агрегированные проверки.
- Доля затронутых страниц используется вместо полного штрафа за единичный URL.
- Каждая категория ограничена своим максимумом, общий результат — диапазоном `0…100`.
- Внутренняя 404 влияет на наблюдаемый HTTP-статус и здоровье перелинковки как на два разных последствия одной причины, но оба вклада ограничены весами и долей страниц.

## Частичная проверка

Проверка помечается `partial`, если общее покрытие меньше `1`, превышен лимит страниц, истёк допустимый тайм-аут или Lighthouse выполнился не для всех выбранных страниц. Клиенту всегда показываются отдельно:

- сколько URL найдено;
- сколько HTML-страниц реально проверено;
- частичный ли результат;
- направления риска без точных URL и доказательств.

Пример: найдена 10-страничная выборка, но проверена одна идеальная страница, Lighthouse недоступен. Покрытие page-based проверок равно `0,1`. Даже при идеальных наблюдениях ограничители дают примерно `60/100`, а не `100/100`; общее покрытие составляет около `0,19`.

Для полностью проверенного сайта без доступного Lighthouse категория скорости получает только наблюдаемый mobile viewport и ограничивается примерно `11/20`; результат явно остаётся частичным.

## Шкала интерпретации

| Балл | Интерпретация |
|---:|---|
| 85–100 | Сильное техническое состояние |
| 70–84 | Хорошее состояние, нужны точечные улучшения |
| 50–69 | Сайт требует системной доработки |
| 30–49 | Высокий SEO-риск |
| 0–29 | Критическое состояние |

## Бесплатный и полный отчёт

Публичный результат содержит только общий балл, уровень, интерпретацию, фактический охват, отметку `partial` и пять общих направлений риска. Он не содержит точных проблем, URL, доказательств или рекомендаций.

Полный административный результат сохраняет проверенные страницы, HTTP-статусы, редиректы, глубину, on-page сигналы, внутренние проблемы, доказательства, рекомендации, category checks, покрытие и доступные Lighthouse-метрики. Расширенный клиентский аудит дополнительно использует доступы к аналитике, поисковым кабинетам, CMS и серверу и поэтому не равен бесплатной шкале.
