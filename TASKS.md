# KILENI SEO — фактический план редизайна

Этот файл заменяет старый список с некорректными отметками «готово». Статус отражает только проверенный результат в интерфейсе, а не наличие отдельных компонентов в коде.

## 1. Общая упаковка и навигация

- [ ] Собрать единый визуальный язык всех публичных страниц: отступы, типографику, поверхности, акцент и поведение на мобильных устройствах.
- [ ] Превратить шапку в компактную плавающую навигацию: Услуги, Кейсы, Цены, Блог, О нас, Бриф; сохранить доступность выпадающих меню.
- [ ] Проверить три полноценные темы — Dark, Signal и Light — на главной, услугах, ценах, кейсах, блоге, брифе и результатах аудита.
- [ ] Вставить согласованные контакты и цветные оригинальные SVG-иконки там, где они помогают действию пользователя.

## 2. Главная страница

- [!] Пересобрать hero как единый экран: точный оффер, форма, доверительные сигналы и живой график видимости без декоративного шума.
- [!] Заменить обычную сетку «как проходит работа» на один понятный интерактивный сценарий из четырёх этапов.
- [ ] Собрать динамический блок выбора следующего действия без стены одинаковых карточек.
- [ ] Перепаковать кейсы, результаты, направления, статьи, FAQ и финальный CTA в единую конверсионную историю.

## 3. Услуги, цены и решения

- [ ] Для каждой услуги сделать структуру «задача → что делаем → что получает клиент → следующий шаг» с понятными результатами.
- [ ] Пересобрать цены через один переключатель категории и уровня, а не через набор несвязанных тарифных карточек.
- [ ] Добавить полноценные сценарии для разработки и маркетплейсов с наглядными артефактами и реальными площадками.
- [ ] Убрать технические и ИИ-формулировки, которые не помогают покупателю выбрать решение.

## 4. Кейсы, блог и доверие

- [!] Перепроверить и показать только подтверждённые результаты кейсов: 35→93, 509/509; 37→80, CLS 0,519→0,0001, 575/575, JSON-LD 0→575.
- [ ] Сделать карточки и детальные страницы кейсов понятными с первого экрана: задача, действия, измеримый результат, доказательства и ограничение.
- [!] Заменить технические иллюстрации в статьях на редакционные фотографии; отдельно проверить все обложки и статьи в UI.
- [ ] Собрать блог как «Базу знаний»: намерение поиска, короткая польза, внутренняя перелинковка, словарь терминов и реальная SEO-структура без обещаний позиций.

## 5. Бриф и бесплатная проверка

- [ ] Сделать бриф коротким диалогом, где клиент понимает цену, состав, сроки и что нужно подготовить, без анкеты «ради полей».
- [!] Ограничить бесплатную проверку до 10 публичных страниц во всех текстах, UI, API и результате.
- [ ] Заменить любой полноэкранный текст при старте проверки на управляемый progress-интерфейс с реальным состоянием.
- [ ] Настроить надёжную отправку результата и PDF на e-mail; не показывать ложный успех при недоступном сервере.
- [ ] Сделать глобальный счётчик завершённых аудитов долговечным только после подключения постоянной БД; не имитировать его на Vercel.

## 6. Проверка перед публикацией

- [ ] Пройти ключевые сценарии на desktop и mobile: меню, темы, форма, аудит, PDF, бриф, цены, кейсы и статьи.
- [ ] Проверить отсутствие горизонтальной/бесконечной прокрутки, анимации с `prefers-reduced-motion`, контраст и клавиатурную навигацию.
- [ ] Собрать production build и зафиксировать реальные блокеры публикации отдельно от визуальной части.
